## Goal
Превратить сайт perf-kaluga.site из страницы одного мероприятия perfeed в постоянный цифровой дом независимой практики современного танца **unlimited position / запредельная позиция** (Анастасия Сенокосова, Калуга). Сайт объясняет практику, показывает актуальную программу и способы присоединиться, представляет автора и даёт контекст. Perfeed становится одним из прошедших событий, и ни одна старая ссылка не ломается.

Визуальная рамка: редакционный сайт европейской performing arts практики (ориентиры — Julidans, Tanz im August, SPRING, ImPulsTanz). Белая основа, тёмная типографика, один приглушённый серо-голубой акцент, крупные фото, асимметричная сетка, lowercase-идентичность. Источник требований — исходное ТЗ пользователя (разделы 1–26) из чата 2026-10-23. Ключевые требования продублированы в этом плане.

## Scope
- Продолжение текущего проекта на Astro (статическая сборка, `astro:assets`, минимум JS). Next.js не используем.
- Согласование дизайна до кода: 2–3 направления, варианты hero, вариант оформления архива.
- Дизайн-система: сетка, типографика, spacing, цвет, система фотографий, поведение на desktop и mobile.
- Главная страница из блоков: hero → statement → сейчас → практика → что происходит в практике → для кого → регулярная практика → анастасия сенокосова → вокруг танца → расписание → стоимость → вопросы → запись → финальный экран.
- Единая data-driven модель событий (`src/data/events.ts`) для актуальных и прошедших событий.
- Перенос текущей главной perfeed на `/events/<slug>` без потерь контента; раздел прошедших событий.

- Базовый URL сайта хранится в одном месте конфигурации.
- Релиз на текущей инфраструктуре с бэкапом и понятным откатом.

## План перехода (раздел 26)

### Карта URL

| Старый URL | Новый URL | Механизм |
|---|---|---|
| `/` (страница лаборатории perfeed) | `/` — главная Unlimited Position | URL тот же, меняется содержимое. Редирект не нужен. Контент лаборатории переезжает на `/events/zoloto-not-dance-2026/` |
| `/#laboratory`, `/#schedule`, `/#hosts`, `/#partners`, `/#contacts` и id заголовков старой главной | `/events/zoloto-not-dance-2026/#<тот же якорь>` | Inline-скрипт на главной: белый список старых якорей → `location.replace`. Новые якоря главной не должны совпадать со старыми |
| `/#top` | `/` (верх новой главной) | Не перенаправляем: якорь общий, исторически вёл на hero |
| `/events`, `/events/` | `/events/` — актуальная программа + прошедшие события | Без изменений пути |
| `/events/challenge-jam-2026-08-15/` | тот же | Без изменений пути и содержимого |
| — | `/events/<slug>/` для новых событий | `getStaticPaths` из `events.ts` |
| — | `/practice/`, `/program/`, `/about/`, `/contact/` | На первом этапе якоря главной. Секции оформлены компонентами, поэтому позже их можно разнести на страницы без переделки |

Почему прошедшие события живут на `/events`, а не на `/archive`. `/events/challenge-jam-2026-08-15` уже существует и распространялся. Единое пространство `/events/<slug>` для актуальных и прошедших событий не даёт конфликтов: slug уникален и содержит дату. Событие, перешедшее из «сейчас» в «прошедшие», не меняет адрес. С `/archive` пришлось бы либо держать два префикса для одного типа сущности, либо делать редиректы при каждом завершении события. Внутри `/events/` две секции: «сейчас / now» и «прошедшие события / past events» (якорь `#past`). Ссылка на `#past` есть в блоке программы и в footer, пятый пункт в основную навигацию не добавляем.

Slug лаборатории: `zoloto-not-dance-2026` (подтверждён пользователем).

### Перенос данных событий
- `event.ts` и `archived-events.ts` сливаются в `src/data/events.ts` (одна коллекция, один тип `Event`). Старые файлы удаляются.
- Общие поля: `slug`, `title`, `type`, `status`, `startDate`, `endDate?`, `dateLabel`, `time?`, `location`, `price?`, `description`, `registrationUrl?`, `image?`, `og?`.
- Типы: `regular_group`, `open_class`, `screening`, `performance`, `laboratory`, `talk` и новый `jam` (челлендж-джем не подходит ни под один исходный тип). Лаборатория perfeed — `laboratory`.
- Статусы: `upcoming`, `open` (идёт запись), `closed` (запись закрыта, событие ещё не прошло), `past`.
- Расширенный контент прошедших событий хранится в опциональных полях: `report?`, `gallery?`, `program?` (расписание), `hosts?`, `partners?`, `contacts?`, `sections?`. Содержимое perfeed переносится дословно. Сохранность проверяем сравнением текстов собранного HTML до и после переноса.

### Оформление архива (выбрать на шаге 1)
- **A. Документ события.** Страница perfeed сохраняет исходный дизайн: стили изолированы в `src/styles/archive/perfeed.css` под корневым классом `.event-doc--perfeed`. Шапка и footer общие (Unlimited Position). Плюсы: событие выглядит так, как его видели участники, контент не потеряется при пересборке. Минусы: на одном сайте два визуальных языка, кислотный `#c8ff00` рядом с серо-голубым.
- **B. Новая визуальная система.** Страница perfeed пересобирается шаблоном события Unlimited Position. Плюсы: целостность и единый шаблон для всех будущих архивных страниц. Минусы: больше работы, больше риск потерь при переносе, исходный образ события теряется.
- Рекомендация: **A** для perfeed и джема (у них собственная айдентика), **B** как шаблон для всех событий Unlimited Position начиная с ноября.

### Порядок релиза и отката
1. Вся разработка идёт в `feature/unlimited-position`. Push в `main` сразу деплоит, поэтому в `main` до релиза ничего не вливается.
2. Перед релизом: `npm run check`, `npm run build`, проверка всех старых URL на локальном `astro preview`, Lighthouse (mobile) для `/`, `/events/`, страницы perfeed.
3. Убедиться, что на сервере есть свежий архив текущей версии в `/var/www/perfeed-backups/` (`deploy.sh` создаёт его сам). Дополнительно сохранить локально `dist/` текущего `main` как эталон.
4. Merge в `main` → GitHub Actions → `deploy.sh`. Инфраструктура, nginx, сертификат, переменные не меняются.
5. Проверка на проде: `/`, `/events/`, `/events/challenge-jam-2026-08-15/`, страница perfeed, старые якоря, OG (превью в Telegram), `robots.txt`, `sitemap.xml`.
6. Откат: распаковать выбранный архив из `/var/www/perfeed-backups` в `/var/www/perfeed`, `nginx -t`, reload, проверить URL (по `SKILL.md`). Или revert merge-коммита и повторный деплой.
